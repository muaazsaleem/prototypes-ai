# Token Smuggling Demonstration

This project provides an educational prototype that demonstrates the token smuggling vulnerability in Large Language Models (LLMs). The demonstration shows how simple token obfuscation techniques bypass early keyword-based input validation filters (Web Application Firewalls or WAFs), allowing restricted instructions to be reconstructed and executed by the model.

## Attack Mechanics

Many legacy safety systems scan incoming prompts for specific forbidden words. Token smuggling circumvents this mechanism by breaking down and reassembling these keywords inside the model itself.

In this demonstration:

1. The user provides a decryption mapping utilizing character substitutions (e.g. substituting digits for letters) without ever using the forbidden words in the prompt.
2. The input filter scans the prompt and finds no blacklisted terms, passing the prompt to the LLM.
3. The LLM processes the translation mapping, reconstructs the forbidden command, and generates the restricted output.

## Setup and Installation

Follow these steps to set up the environment and run the prototype.

1. Ensure Python 3.10+ is installed on your system.
2. Create and activate a virtual environment.
3. Install the dependencies:
```bash
./venv/bin/pip install -q -U google-genai rich
```
4. Set your Gemini API key:
```bash
export GEMINI_API_KEY="your_api_key_here"
```

## Running the Prototype

Execute the main script to run the demonstration:
```bash
./venv/bin/python main.py
```

The script runs two separate tests:

- A direct request containing literal forbidden terms (e.g. `DROP ALL TABLES`), which is intercepted and blocked by the simulated input guard.
- A smuggled request containing character-substituted terms (e.g. `DR0P 4LL 74BL35`), which successfully bypasses the input guard and triggers the LLM to output the forbidden instructions.

## Defenses and Mitigation

Traditional string-matching input filters do not protect against token smuggling. Securing LLM applications requires multi-layered defensive strategies:

- Dual-pass input sanitization: Run prompts through a secondary, lightweight LLM specifically trained to detect obfuscation techniques, substitution games, or malicious intent before sending them to the main model.
- Output guardrails: Evaluate the generated output of the LLM using semantic checkers (such as LlamaGuard) before returning it to the user. Since the output generated by the LLM is literal (e.g. producing actual `DROP TABLE` queries), an output guardrail will easily intercept and block the response.
- System instruction tuning: Program the system instructions of the LLM to actively identify and reject roleplay scenarios, translation games, or substitution tables that seek to perform prohibited actions.
- Hard output scanning: Implement deterministic scanners on the output layer to block sensitive patterns and keywords from being leaked or delivered to the client.
